## 节点 22：设计用户、老师、课程与章节表（1.5～2 小时）

### 本节点目标

建立课程内容系统的核心关系和数据库约束。

### 当前节点使用的技术能力

- **关系建模**：用户、老师、课程、章节通过主键和外键关联。

```ts
export * from "./core";
```

### 原理说明

链上 `uint256` 和 token amount 可能超过 JavaScript 安全整数，因此数据库先用十进制字符串保存，应用边界再转换 `BigInt`。钱包地址写入前统一 `getAddress(address).toLowerCase()` 或统一 checksum，不能混用。用户名展示值写 `username`，唯一比较值写 `usernameNormalized`：先执行 Unicode NFKC 规范化，再对英文字母小写化，避免 `Alice` 和 `alice` 占用两个名称。

## 节点 25：组织 tRPC Router、错误和权限层（1～1.5 小时）

### 本节点目标

建立公开、登录、角色权限三层 Procedure，避免每个接口重复写检查。

### 当前节点使用的技术能力

- **tRPC middleware**：在业务 procedure 前执行认证和授权。
- **Context**：为单次请求提供用户和数据库对象。
- **TRPCError**：返回稳定错误码，不让前端分析错误字符串。

### 关键代码

更新 `packages/api/src/context.ts` 返回：

```ts
return {
  hono: options.context,
  auth: null as null | { privyUserId: string },
  user: null as null | {
    id: string;
    walletAddress: string;
    role: "student" | "teacher" | "operator" | "admin";
  },
};
```

在 `packages/api/src/index.ts` 加入：

```ts
import { TRPCError } from "@trpc/server";

const requireAuth = t.middleware(({ ctx, next }) => {
  if (!ctx.auth) {
    throw new TRPCError({ code: "UNAUTHORIZED" });
  }
  return next({ ctx: { ...ctx, auth: ctx.auth } });
});

const requireUser = t.middleware(({ ctx, next }) => {
  if (!ctx.auth || !ctx.user) {
    throw new TRPCError({ code: "UNAUTHORIZED" });
  }
  return next({ ctx: { ...ctx, auth: ctx.auth, user: ctx.user } });
});

// Privy token 有效，但用户可能尚未绑定钱包和创建本地资料。
export const authenticatedProcedure = t.procedure.use(requireAuth);

// Privy token 有效，并且本地用户已经完成建档。
export const protectedProcedure = t.procedure.use(requireUser);

type AppRole = "student" | "teacher" | "operator" | "admin";

export const roleProcedure = (roles: readonly AppRole[]) =>
  protectedProcedure.use(({ ctx, next }) => {
    if (!roles.includes(ctx.user.role)) {
      throw new TRPCError({ code: "FORBIDDEN" });
    }
    return next({ ctx });
  });
```

### 原理说明

认证回答“你是谁”，授权回答“你能做什么”。两者不能混成一个 `isAdmin` 前端字段。`authenticatedProcedure` 专门处理首次登录但还没有数据库用户的建档流程；普通业务使用 `protectedProcedure`。

### 验证

创建临时 `me` protected query，未登录请求应得到 `UNAUTHORIZED`，不是 500。

## 节点 26：接入 Privy 后端身份验证（1.5～2 小时）

### 本节点目标

后端验证 Privy Access Token，并把 Privy 用户映射到数据库用户。

### 当前节点使用的技术能力

- **Bearer token**：前端通过 Authorization header 发送短期 Access Token。
- **JWT verification**：验证签名、签发方、appId 和过期时间。
- **Identity mapping**：Privy DID 映射到本地 user，而不是信任前端 walletAddress。

### 操作步骤

```bash
pnpm --filter @web3-school/api add @privy-io/node
```

在 `context.ts` 初始化客户端：

```ts
import { PrivyClient } from "@privy-io/node";
import { db } from "@web3-school/db";
import { users } from "@web3-school/db/schema/core";
import { eq } from "drizzle-orm";
import { env } from "@web3-school/env/server";

const privy = new PrivyClient({
  appId: env.PRIVY_APP_ID,
  appSecret: env.PRIVY_APP_SECRET,
});
```

在 `createContext` 中：

```ts
const header = options.context.req.header("authorization");
if (!header?.startsWith("Bearer ")) {
  return { hono: options.context, auth: null, user: null };
}

try {
  const claims = await privy.verifyAuthToken(header.slice(7));
  const [user] = await db
    .select()
    .from(users)
    .where(eq(users.privyUserId, claims.userId))
    .limit(1);
  return {
    hono: options.context,
    auth: { privyUserId: claims.userId },
    user: user ?? null,
  };
} catch {
  return { hono: options.context, auth: null, user: null };
}
```

SDK 方法签名可能随版本变化，安装后以 TypeScript 自动提示和 Privy 当前 Access Token 文档为准；不能改成 `jwt.decode()` 而跳过验证。

首次建档必须再证明钱包控制权：

1. `auth.bindingNonce` 使用 `authenticatedProcedure` 生成 10 分钟 nonce。
2. 前端签署固定格式消息：

```text
Web3 University wallet binding
Privy User: <privy-user-id>
Wallet: <0x-address>
Nonce: <bytes32>
Deadline: <unix-seconds>
```

3. `auth.bindWallet` 使用 `authenticatedProcedure`，从 token 中读取 Privy DID，不接受前端覆盖。
4. 后端用 viem 验证钱包：

```ts
const valid = await verifyMessage({
  address: input.walletAddress,
  message: expectedMessage,
  signature: input.signature,
});
if (!valid) throw new TRPCError({ code: "UNAUTHORIZED" });
```

5. 在数据库事务中消费 nonce，并用 Privy DID、规范化 walletAddress 创建用户。相同 wallet 已绑定其他 Privy DID 时拒绝。

### 验证

- 无 token：public 可访问、protected 401。
- 伪造 token：protected 401。
- 有效 token 且已有用户：`me` 返回数据库资料。

### 常见错误

- 发送 Identity Token 给 `verifyAuthToken`：它只验证 Access Token。
- 把 App Secret 放前端：严重泄露，只能在 Server。

### 验收清单

- [ ] Access Token 经过密码学验证。
- [ ] App Secret 不在 Vite 环境变量。
- [ ] 用户钱包经过签名绑定。

## 节点 27：实现公开课程列表与详情 API（1.5～2 小时）

### 本节点目标

游客能分页查看 active 课程，详情中不泄露完整视频资源地址。

### 当前节点使用的技术能力

- **Zod input**：限制分页范围和 ID 格式。
- **Selective projection**：只查询公开列。
- **Pagination**：避免一次返回全部课程。

### 关键代码

创建 `packages/api/src/routers/courses.ts`：

```ts
import { courses } from "@web3-school/db/schema/core";
import { and, eq, ilike } from "drizzle-orm";
import { z } from "zod";
import { publicProcedure, router } from "../index";
import { db } from "@web3-school/db";

export const coursesRouter = router({
  list: publicProcedure
    .input(z.object({
      page: z.number().int().min(1).default(1),
      pageSize: z.number().int().min(1).max(50).default(20),
      keyword: z.string().trim().max(80).optional(),
    }))
    .query(async ({ input }) => {
      const where = and(
        eq(courses.status, "active"),
        input.keyword ? ilike(courses.title, `%${input.keyword}%`) : undefined,
      );
      return db.select({
        id: courses.id,
        chainCourseId: courses.chainCourseId,
        title: courses.title,
        coverUrl: courses.coverUrl,
        priceYd: courses.priceYd,
      }).from(courses).where(where)
        .limit(input.pageSize)
        .offset((input.page - 1) * input.pageSize);
    }),
});
```

详情 query 使用 `z.string().uuid()`，只返回章节标题、顺序、时长；`videoAssetId` 只有购买校验后的学习接口返回短期播放 URL。

在根 router 注册：

```ts
export const appRouter = router({
  healthCheck: publicProcedure.query(() => "OK"),
  courses: coursesRouter,
});
```

### 本节点目标

实现 `draft → pending_review → pending_chain → active` 状态机。

### 当前节点使用的技术能力

- **State machine**：只允许明确的状态转换。
- **Transaction boundary**：数据库多步更新要么全部成功，要么全部回滚。
- **Role authorization**：老师只能改自己的草稿，Operator/Admin 才能审核。

### 操作步骤

实现以下 procedures：

```text
teacher.createDraft
teacher.updateDraft
teacher.submitForReview
admin.approveCourse
admin.rejectCourse
admin.confirmOnchainListing
```

状态转换函数集中定义：

```ts
const transitions = {
  draft: ["pending_review"],
  pending_review: ["rejected", "pending_chain"],
  rejected: ["draft"],
  pending_chain: ["active"],
  active: ["paused"],
  paused: ["active", "archived"],
} as const;
```

`approveCourse` 只把课程改成 `pending_chain`。运营人员完成链上 `createCourse` 并验证 receipt 后，`confirmOnchainListing` 才写 `chainCourseId/txHash` 并改成 active。

## 节点 29：实现链上购买交易验证（1.5～2 小时）

### 本节点目标

后端根据 receipt 中的真实 `CoursePurchased` 事件开放课程，而不是相信前端。

### 当前节点使用的技术能力

- **viem Public Client**：读取 Sepolia receipt、block 和合约状态。
- **ABI log decoding**：把事件 topics/data 还原为 buyer/courseId/price。
- **Idempotent insert**：重复提交相同 txHash 不重复授权。

### 操作步骤


```ts
const receipt = await publicClient.waitForTransactionReceipt({
  hash: input.txHash,
  confirmations: 2,

const decodedLogs = parseEventLogs({
```

## 节点 32：实现用户名签名与 EIP-712 证书证明（1.5～2 小时）

### 本节点目标

完成两个签名方向：用户签名修改用户名；服务器签名课程完成证明。

### 当前节点使用的技术能力

- **viem verifyTypedData**：后端验证钱包 EIP-712 签名。
- **Local account signing**：服务器证明签名私钥只存在 Server 环境。
- **Atomic nonce consumption**：验证和消费在同一数据库事务中完成。

### 用户名签名

类型定义：

```ts
const profileTypes = {
  UpdateUsername: [
    { name: "wallet", type: "address" },
    { name: "username", type: "string" },
    { name: "nonce", type: "bytes32" },
    { name: "deadline", type: "uint256" },
  ],
} as const;
```

后端生成随机 nonce 和 10 分钟 deadline。验证：


### 课程完成证明

```ts
import { privateKeyToAccount } from "viem/accounts";
import { keccak256, stringToHex } from "viem";
import { randomBytes } from "node:crypto";

const signer = privateKeyToAccount(env.COURSE_PROOF_SIGNER_PRIVATE_KEY);
const nonce = `0x${randomBytes(32).toString("hex")}` as const;
const deadline = BigInt(Math.floor(Date.now() / 1000) + 10 * 60);

const signature = await signer.signTypedData({
  domain: {
    name: "Web3 University Certificate",
    version: "1",
    chainId: 11155111,
    verifyingContract: certificateAddress,
  },
  types: {
    CourseCompletion: [
      { name: "student", type: "address" },
      { name: "courseId", type: "uint256" },
      { name: "tokenURIHash", type: "bytes32" },
      { name: "nonce", type: "bytes32" },
      { name: "deadline", type: "uint256" },
    ],
  },
  primaryType: "CourseCompletion",
  message: {
    student: ctx.user.walletAddress,
    courseId: BigInt(course.chainCourseId!),
    tokenURIHash: keccak256(stringToHex(tokenUri)),
    nonce,
    deadline,
  },
});
```

只有 completed 且尚无 certificates 记录时返回证明。

### 常见错误

- Server signer 地址没有被授予合约 `SIGNER_ROLE`，签名正确也会失败。
- Node crypto 生成的 nonce 要固定成 32 bytes。
- JS 时间是毫秒，Solidity 时间是秒。

用户名写入前生成规范化值：

```ts
const usernameNormalized = input.username
  .normalize("NFKC")
  .toLocaleLowerCase("en-US");
```

在同一事务中写 `username`、`usernameNormalized` 并消费 nonce；唯一约束冲突返回 `CONFLICT`。

- [ ] 用户名签名地址等于绑定钱包。
- [ ] 完成证明字段与 Solidity TYPEHASH 完全一致。
- [ ] 私钥不返回前端。
