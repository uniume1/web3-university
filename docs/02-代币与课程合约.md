## 节点 07：理解 ERC-20、单位和 allowance（1～1.5 小时）

### 本节点目标

理解购买流程涉及的余额、精度、授权和转账角色，先不写业务合约。

### 当前节点使用的技术能力

- **ERC-20**：同质化代币接口，定义 `balanceOf`、`transfer`、`approve`、`transferFrom`。
- **decimals**：只影响 UI 如何解释整数；EVM 不存小数。
- **allowance**：代币持有人允许另一个地址最多代扣多少。
- **SafeERC20**：兼容不严格返回布尔值的 ERC-20，并统一失败处理。

### 必须理解的购买关系

```text
学生钱包 --approve(4 YD)--> CourseMarket 获得额度
学生钱包 --buy(courseId)--> CourseMarket
CourseMarket --transferFrom--> 学生的 4 YD 转入 treasury
```

价格永远使用最小单位：

```solidity
4 YD = 4 * 10**18 = 4 ether
4 MockUSDC = 4 * 10**6
```

### 操作步骤

用 Chisel 观察单位：

```bash
chisel
```

```solidity
uint256(4 ether)
uint256(4 * 10**6)
```

阅读 OpenZeppelin 当前 ERC-20 文档和 `IERC20.sol`，列出四个参与者：学生、代币合约、课程市场、平台金库。

### 验证

你应该能回答：为什么用户不能只调用 `buy()`？因为 CourseMarket 无权直接移动用户的 YD，必须先获得 allowance。

### 常见错误

- `4` 不是 4 YD，而是 4 个最小单位。
- `approve` 不会转账，只会写 allowance。
- allowance 应授权给 `CourseMarket`，不是 treasury。

- [ ] 能解释 `transfer` 与 `transferFrom`。
- [ ] 能计算 YD 和 MockUSDC 最小单位。
- [ ] 能画出 approve + buy 调用关系。

## 节点 08：实现固定总量 `YDToken`（1.5～2 小时）

### 本节点目标

实现一次性发行、不可继续增发的 1 亿枚 YD。

### 当前节点使用的技术能力

- **Solidity inheritance**：继承 OpenZeppelin ERC20，复用标准实现。
- **Constructor mint**：只在部署时铸造固定总量。
- **Immutable economic rule**：合约中没有外部 `mint`，管理员也不能增发。

### 关键代码

创建 `apps/contracts/src/YDToken.sol`：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.30;

import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract YDToken is ERC20 {
    uint256 public constant INITIAL_SUPPLY = 100_000_000 ether;

    error ZeroTreasury();

    constructor(address treasury) ERC20("YD Token", "YD") {
        if (treasury == address(0)) revert ZeroTreasury();
        _mint(treasury, INITIAL_SUPPLY);
    }
}
```

### 原理说明

OpenZeppelin ERC20 默认 `decimals()` 为 18。`100_000_000 ether` 只是 Solidity 的十进制单位语法，等于 `100_000_000 * 10**18`，不代表 ETH 被转入合约。

### 验证

```bash
cd apps/contracts
forge fmt
forge build
forge inspect YDToken abi
```

### 常见错误

- 添加 `onlyOwner mint`：这破坏固定总量要求，不添加。
- treasury 设为合约自身：代币会锁住；部署时使用明确的钱包或多签地址。

- [ ] 名称和 Symbol 正确。
- [ ] 总量固定为 1 亿 YD。
- [ ] 零地址 treasury 会失败。

## 节点 09：实现 6 位精度 `MockUSDC`（1～1.5 小时）

### 本节点目标

提供仅用于测试的 USDC 替代物，避免依赖第三方测试币 Faucet。

### 当前节点使用的技术能力

- **ERC-20 decimals override**：模拟真实 USDC 常见的 6 位精度。
- **Test token faucet**：任何人可领取少量测试币，只允许用于测试网。
- **Rate/limit guard**：限制单次领取，防止误用为正式资产。

### 关键代码

创建 `apps/contracts/src/MockUSDC.sol`：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.30;

import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract MockUSDC is ERC20 {
    uint256 public constant FAUCET_AMOUNT = 1_000 * 10**6;

    constructor(address initialHolder) ERC20("Mock USD Coin", "mUSDC") {
        _mint(initialHolder, 10_000_000 * 10**6);
    }

    function decimals() public pure override returns (uint8) {
        return 6;
    }

    function faucet() external {
        _mint(msg.sender, FAUCET_AMOUNT);
    }
}
```

### 原理说明

该 faucet 可以无限调用，所以 MockUSDC 没有经济价值。页面必须显示 `mUSDC` 和“测试代币”，不能假装它是真 USDC。

## 节点 12：实现课程创建、更新和暂停（1.5～2 小时）

### 本节点目标

实现 `CourseMarket` 管理部分。

### 当前节点使用的技术能力

- **Role modifier**：`onlyRole(OPERATOR_ROLE)` 在执行函数前检查权限。
- **Storage struct**：课程核心交易数据永久保存在链上。
- **Hash commitment**：`metadataHash` 用于检测链下课程元数据是否被替换。

### 关键代码（第一部分）

创建 `apps/contracts/src/CourseMarket.sol`：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.30;

import {AccessControl} from "@openzeppelin/contracts/access/AccessControl.sol";
import {ReentrancyGuard} from "@openzeppelin/contracts/utils/ReentrancyGuard.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import {SafeERC20} from "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";

contract CourseMarket is AccessControl, ReentrancyGuard {
    using SafeERC20 for IERC20;

    bytes32 public constant OPERATOR_ROLE = keccak256("OPERATOR_ROLE");

    struct Course {
        address teacher;
        uint256 price;
        bytes32 metadataHash;
        bool active;
        bool exists;
    }

    IERC20 public immutable ydToken;
    address public immutable treasury;
    mapping(uint256 => Course) public courses;
    mapping(address => mapping(uint256 => bool)) public purchased;

    error ZeroAddress();
    error InvalidCourse();
    error CourseAlreadyExists();
    error CourseNotActive();
    error AlreadyPurchased();

    event CourseCreated(
        uint256 indexed courseId,
        address indexed teacher,
        uint256 price,
        bytes32 metadataHash
    );
    event CourseUpdated(
        uint256 indexed courseId,
        uint256 price,
        bytes32 metadataHash,
        bool active
    );
    event CoursePurchased(
        address indexed buyer,
        uint256 indexed courseId,
        uint256 price
    );

    constructor(address token, address treasury_, address admin) {
        if (token == address(0) || treasury_ == address(0) || admin == address(0)) {
            revert ZeroAddress();
        }
        ydToken = IERC20(token);
        treasury = treasury_;
        _grantRole(DEFAULT_ADMIN_ROLE, admin);
        _grantRole(OPERATOR_ROLE, admin);
    }

    function createCourse(
        uint256 courseId,
        address teacher,
        uint256 price,
        bytes32 metadataHash
    ) external onlyRole(OPERATOR_ROLE) {
        if (courseId == 0 || teacher == address(0) || price == 0) {
            revert InvalidCourse();
        }
        if (courses[courseId].exists) revert CourseAlreadyExists();

        courses[courseId] = Course({
            teacher: teacher,
            price: price,
            metadataHash: metadataHash,
            active: true,
            exists: true
        });
        emit CourseCreated(courseId, teacher, price, metadataHash);
    }

    function updateCourse(
        uint256 courseId,
        uint256 price,
        bytes32 metadataHash,
        bool active
    ) external onlyRole(OPERATOR_ROLE) {
        Course storage course = courses[courseId];
        if (!course.exists || price == 0) revert InvalidCourse();
        course.price = price;
        course.metadataHash = metadataHash;
        course.active = active;
        emit CourseUpdated(courseId, price, metadataHash, active);
    }
```

节点 13 会在同一合约补充 `buy` 并闭合大括号。

## 节点 13：实现 `approve + buy`（1.5～2 小时）

### 本节点目标

让课程市场代扣 YD、记录购买并发出事件。

### 当前节点使用的技术能力

- **Checks-Effects-Interactions**：先检查，再更新状态，最后外部调用。
- **ReentrancyGuard**：防止恶意代币或未来改动形成重入。
- **SafeERC20.safeTransferFrom**：安全执行代扣。
- **Event indexing**：`buyer`、`courseId` 使用 indexed 便于筛选。

### 关键代码

在 `CourseMarket` 结束大括号前加入：

```solidity
    function buy(uint256 courseId) external nonReentrant {
        Course memory course = courses[courseId];
        if (!course.exists || !course.active) revert CourseNotActive();
        if (purchased[msg.sender][courseId]) revert AlreadyPurchased();

        purchased[msg.sender][courseId] = true;
        ydToken.safeTransferFrom(msg.sender, treasury, course.price);

        emit CoursePurchased(msg.sender, courseId, course.price);
    }

    function hasPurchased(address buyer, uint256 courseId)
        external
        view
        returns (bool)
    {
        return purchased[buyer][courseId];
    }
```

### 原理说明

先写 `purchased=true` 再转账符合 CEI。如果转账失败，整笔交易 revert，状态也会回滚，不会出现“扣款失败但已购买”。

### 验证

```bash
forge fmt --check
forge build
```

### 常见错误

- 用 `transfer`：这会从 CourseMarket 自己余额转出，不是从学生余额代扣。
- 接收前端传入价格：攻击者可以传 0；价格必须读 `courses[courseId].price`。
- 先转账再记录购买：当前代码虽有重入保护，但仍应保持 CEI。

pragma solidity ^0.8.30;

import {Test} from "forge-std/Test.sol";
import {YDToken} from "../src/YDToken.sol";
import {CourseMarket} from "../src/CourseMarket.sol";

contract CourseMarketTest is Test {
    YDToken internal yd;
    CourseMarket internal market;
    address internal admin = makeAddr("admin");
    address internal treasury = makeAddr("treasury");
    address internal teacher = makeAddr("teacher");
    address internal student = makeAddr("student");

    uint256 internal constant PRICE = 4 ether;

    function setUp() public {
        yd = new YDToken(treasury);
        market = new CourseMarket(address(yd), treasury, admin);

        vm.prank(treasury);
        yd.transfer(student, 100 ether);

        vm.prank(admin);
        market.createCourse(
            COURSE_ID,
            teacher,
            PRICE,
            keccak256("course-1-metadata")
        );
    }

    function testStudentCanApproveAndBuy() public {
        vm.startPrank(student);
        yd.approve(address(market), PRICE);
        market.buy(COURSE_ID);
        vm.stopPrank();

        assertTrue(market.hasPurchased(student, COURSE_ID));
        assertEq(yd.balanceOf(student), 96 ether);
        assertEq(yd.balanceOf(treasury), yd.totalSupply() - 96 ether);
    }

    function testBuyFailsWithoutAllowance() public {
        vm.prank(student);
        vm.expectRevert();
        market.buy(COURSE_ID);
    }

    function testCannotBuyTwice() public {
        vm.startPrank(student);
        yd.approve(address(market), PRICE * 2);
        market.buy(COURSE_ID);
        vm.expectRevert(CourseMarket.AlreadyPurchased.selector);
        market.buy(COURSE_ID);
        vm.stopPrank();
    }

    function testCannotBuyPausedCourse() public {
        vm.prank(admin);
        market.updateCourse(COURSE_ID, PRICE, bytes32(0), false);

        vm.startPrank(student);
        yd.approve(address(market), PRICE);
        vm.expectRevert(CourseMarket.CourseNotActive.selector);
        market.buy(COURSE_ID);
        vm.stopPrank();
    }

    function testNonOperatorCannotCreateCourse() public {
        vm.prank(student);
        vm.expectRevert();
        market.createCourse(2, teacher, PRICE, bytes32(0));
    }
}

import {YDToken} from "../src/YDToken.sol";
import {MockUSDC} from "../src/MockUSDC.sol";
import {CourseMarket} from "../src/CourseMarket.sol";

contract DeployCore is Script {

## 节点 16：部署到 Sepolia 并验证源码（1.5～2 小时）

### 本节点目标

获得测试 ETH，把核心合约部署到 Ethereum Sepolia，并保存可验证地址。

### 当前节点使用的技术能力

- **Public testnet RPC**：与共享 Ethereum 测试网络通信。
- **Faucet**：领取没有真实价值的测试 ETH。
- **Block explorer verification**：公开源代码、编译参数和 bytecode 对应关系。
- **Confirmation**：等待多个区块降低短暂重组影响。

### 操作步骤

1. 新建只用于开发的测试钱包。
2. 从可信 Sepolia Faucet 获取少量 ETH。
3. 从 Alchemy/Infura 获取 Sepolia RPC。
4. 在 `apps/contracts/.env` 填写 RPC、测试钱包私钥和 Etherscan API Key。
5. 检查网络与余额：

```bash
source .env
cast chain-id --rpc-url "$SEPOLIA_RPC_URL"
cast wallet address --private-key "$DEPLOYER_PRIVATE_KEY"
cast balance <DEPLOYER_ADDRESS> --ether --rpc-url "$SEPOLIA_RPC_URL"
```

Chain ID 必须为 `11155111`。部署：

```bash
forge script script/DeployCore.s.sol:DeployCore \
  --rpc-url "$SEPOLIA_RPC_URL" \
  --broadcast \
  --verify \
  -vvvv
```

创建 `apps/contracts/deployments/sepolia.json`，只保存公开信息：

```json
{
  "chainId": 11155111,
  "deployedAtBlock": 0,
  "YDToken": "0x...",
  "MockUSDC": "0x...",
  "CourseMarket": "0x..."
}
```

使用 Cast 检查：

```bash
cast call <YD_ADDRESS> "totalSupply()(uint256)" --rpc-url "$SEPOLIA_RPC_URL"
cast call <MARKET_ADDRESS> "treasury()(address)" --rpc-url "$SEPOLIA_RPC_URL"
```

### 原理说明

`broadcast` 文件包含交易记录但不应包含明文私钥。公开测试网部署也是真实不可逆交易，只是使用无价值测试 ETH。

### 常见错误

- Chain ID 不是 11155111：立即停止，RPC 网络填错。
- 验证失败但部署成功：不要重复部署；使用 `forge verify-contract` 单独验证。
- Faucet 不到账：等待或换官方推荐 Faucet，不购买所谓“测试 ETH”。

### 验收清单

- [ ] 三个地址在 Sepolia Etherscan 有代码。
- [ ] 源码已验证或记录了单独验证步骤。
- [ ] `sepolia.json` 不含私钥。
- [ ] Cast 能读取总量和 treasury。

### Git 提交建议

```bash
git add apps/contracts/deployments/sepolia.json
git commit -m "chore(contracts): record sepolia core deployments"
```
