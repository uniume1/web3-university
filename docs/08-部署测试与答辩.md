> 节点范围：53～56

> 预计用时：6～8 小时

## 节点 53：安全检查、密钥和环境变量清理（1.5～2 小时）

### 本节点目标

在上传代码和部署前排除最常见的私钥、权限和错误网络事故。

### 当前节点使用的技术能力

- **Secret hygiene**：识别敏感键、确认 Git ignore、必要时轮换。
- **Static checks**：类型、格式、构建和合约测试。
- **Least privilege review**：管理员、Operator、Signer 和 treasury 分工。
- **Deployment diff review**：确认即将发布的 commit 和地址。

### 操作步骤

```bash
git status --short
git diff --check
git ls-files | rg '(^|/)\.env($|\.)'
git grep -nE '(PRIVATE_KEY|APP_SECRET|postgresql://|BEGIN PRIVATE KEY)'
pnpm check-types
pnpm check
pnpm build
cd apps/contracts
forge fmt --check
forge test -vvv
forge build --sizes
```

`git grep` 命中 `.env.example` 的键名可能正常，但不得出现真实值。检查合约角色：

```bash
cast call <MARKET> "hasRole(bytes32,address)(bool)" <OPERATOR_ROLE> <OPERATOR>
cast call <CERT> "hasRole(bytes32,address)(bool)" <SIGNER_ROLE> <SIGNER>
```

检查网络：所有前端共享地址均属于 Chain ID 11155111。

### 常见错误

- 曾经提交过密钥后只删除当前文件：Git 历史仍有，必须立即轮换。
- `pnpm check` 带 `--write` 可能修改文件，执行后必须 review diff。
- 测试钱包也不要公开私钥；它可能持有第三方 Faucet 资源或角色权限。

### 验收清单

- [ ] Git 未跟踪任何真实 env。
- [ ] 类型、构建、Forge 测试通过。
- [ ] 合约地址和 Chain ID 一致。
- [ ] 角色地址有记录。

### Git 提交建议

```bash
git add -A
git diff --cached
git commit -m "chore(release): prepare MVP deployment"
```

## 节点 54：部署 Web、Server 和数据库到 Vercel（1.5～2 小时）

### 本节点目标

使用脚手架已生成的 Vercel Services 配置部署 Web 和 Hono Server，并连接长期数据库。

### 当前节点使用的技术能力

- **Vercel Services**：同一项目部署 Web 与 Server，`/api/*` rewrite 到 Hono。
- **Environment scopes**：Development、Preview、Production 配置隔离。
- **Database migration**：部署前明确执行，不在每次冷启动自动改 schema。
- **CORS/same-origin**：生产通过同域 `/api` 简化跨域。

### 环境变量清单

Server：

```text
DATABASE_URL
CORS_ORIGIN
PRIVY_APP_ID
PRIVY_APP_SECRET
SEPOLIA_RPC_URL
COURSE_PROOF_SIGNER_PRIVATE_KEY
NODE_ENV
```

Web：

```text
VITE_SERVER_URL=/api
VITE_PRIVY_APP_ID
VITE_SEPOLIA_RPC_URL
VITE_YD_TOKEN_ADDRESS
VITE_COURSE_MARKET_ADDRESS
VITE_CERTIFICATE_ADDRESS
```

### 操作步骤

先确认 Prisma Postgres 是长期实例并备份连接串。执行 production migration：

```bash
pnpm db:migrate
```

关联项目并做 dry run：

```bash
pnpm deploy:setup
pnpm deploy:check
```

通过 Vercel Dashboard 设置环境变量比批量上传本地 `.env` 更容易审查。先 Preview：

```bash
pnpm deploy
```

将 Preview 域名加入 Privy Allowed Origins。测试通过后：

```bash
pnpm deploy:prod
```

### 原理说明

不要在 Hono 启动时自动执行 migration；Serverless 多实例并发启动可能同时改 schema。

### 常见错误

- 前端请求 `/trpc` 404：生产 `VITE_SERVER_URL` 和 `vercel.json` rewrite 不一致。
- Privy 登录拒绝：部署域名未加入 Dashboard。
- Functions API 被 Preview Protection 拦截：为 oracle 路径设置合适访问策略，不能把整个后台设为公开无鉴权。

### 验收清单

- [ ] Preview 健康检查成功。
- [ ] 数据库 migration 已执行一次。
- [ ] Privy 允许部署域名。
- [ ] Secret 不出现在浏览器 bundle。

### Git 提交建议

通常部署不产生代码；如调整 `vercel.json`：

```bash
git add vercel.json README.md
git commit -m "fix(deploy): align Vercel service routing"
```

## 节点 55：执行完整端到端验收（1.5～2 小时）

### 本节点目标

用不同角色、不同浏览器会话证明每个系统边界正确。

### 当前节点使用的技术能力

- **E2E scenario testing**：从用户行为验证跨层系统，而不是只看单元测试。
- **Role isolation**：管理员、老师和学生使用独立会话。
- **Evidence collection**：保存公开交易 hash、requestId、截图和预期结果。

### 测试账户

```text
Account A：admin/Operator/部署者（测试钱包）
Account B：老师
Account C：学生
Account D：未购买学生/攻击路径
```

### 主流程

1. B 登录并绑定钱包。
2. A 把 B 设置为 teacher，并批准老师资料。
3. B 创建课程、章节并提交审核。
4. A 审核，调用 CourseMarket 创建 4 YD 课程。
5. C 登录，从 mUSDC/WETH 兑换 YD。
6. C approve 4 YD。
7. C buy，等待 2 confirmations。
8. 后端验证 tx，C 获得学习权限。
9. C 学习到 90%，测验及格，发表评论。
10. C 使用 EIP-712 或 Chainlink 路径领取证书。
11. 个人中心展示购买、进度和 NFT。

### 失败流程

- D 直接打开学习页，应 FORBIDDEN。
- D 提交 C 的购买 txHash，应失败。
- C 重复 buy，应合约 revert。
- C 重复使用用户名 nonce，应失败。
- C 篡改证书 tokenURI，应 InvalidSigner。
- C transfer 证书，应 Soulbound revert。
- B 访问管理员 API，应 FORBIDDEN。
- 暂停课程后新用户购买，应失败；旧购买记录不消失。

### 验收记录模板

```text
场景：C 购买课程
时间：
用户地址：
课程 ID：
approve tx：
buy tx：
后端 purchase ID：
结果：通过/失败
备注：
```

### 验收清单

- [ ] 主流程 11 步全部通过。
- [ ] 八个失败流程行为符合预期。
- [ ] 交易证据可公开验证。
- [ ] 没有使用生产真实资金。

### Git 提交建议

如果保存脱敏验收记录：

```bash
git add docs
git commit -m "docs: record MVP acceptance results"
```

## 节点 56：完善 README、演示脚本和答辩材料（1～1.5 小时）

### 本节点目标

让没有参与开发的人能启动项目，并让你能在 8～10 分钟内讲清产品、技术和取舍。


## 完整执行附录

本章的 `<MARKET>`、`<CERT>` 等内容是部署环境占位符，不应被编造成固定地址。执行前统一在终端设置公开地址：

```bash
export YD_ADDRESS=0x实际UNIToken地址
export MARKET_ADDRESS=0x实际CourseMarket地址
export CERTIFICATE_ADDRESS=0x实际CourseCertificate地址
export ORACLE_ADDRESS=0x实际CourseCompletionOracle地址
export OPERATOR_ADDRESS=0x实际Operator钱包地址
export SIGNER_ADDRESS=0x实际证明签名地址
```

### A. 本地质量检查

从项目根目录执行：

```bash
nvm use
pnpm install --frozen-lockfile
pnpm check-types
pnpm check
pnpm build

cd apps/contracts
forge fmt --check
forge build --sizes
forge test -vvv
cd ../..
```

任何一步失败都不能进入部署。

### B. 密钥泄露检查

只搜索变量名和典型私钥格式，不打印 `.env` 内容：

```bash
git status --short
git check-ignore apps/server/.env apps/web/.env apps/contracts/.env

rg -n --hidden \
  --glob '!**/.env' \
  --glob '!**/node_modules/**' \
  --glob '!**/.git/**' \
  'PRIVATE_KEY=0x[0-9a-fA-F]{64}|APP_SECRET=.+|/v2/[A-Za-z0-9_-]{16,}' .
```

如果 Git 历史曾提交真实密钥，仅从当前文件删除不够，必须轮换密钥。

### C. Sepolia 合约检查

```bash
source apps/contracts/.env

cast chain-id --rpc-url "$SEPOLIA_RPC_URL"
cast code "$YD_ADDRESS" --rpc-url "$SEPOLIA_RPC_URL"
cast code "$MARKET_ADDRESS" --rpc-url "$SEPOLIA_RPC_URL"
cast code "$CERTIFICATE_ADDRESS" --rpc-url "$SEPOLIA_RPC_URL"
```

Chain ID 必须是：

```text
11155111
```

三个 `cast code` 结果都不能是 `0x`。

读取配置关系：

```bash
cast call "$MARKET_ADDRESS" \
  "uniToken()(address)" \
  --rpc-url "$SEPOLIA_RPC_URL"

cast call "$MARKET_ADDRESS" \
  "treasury()(address)" \
  --rpc-url "$SEPOLIA_RPC_URL"

export OPERATOR_ROLE=$(cast keccak "OPERATOR_ROLE")
cast call "$MARKET_ADDRESS" \
  "hasRole(bytes32,address)(bool)" \
  "$OPERATOR_ROLE" "$OPERATOR_ADDRESS" \
  --rpc-url "$SEPOLIA_RPC_URL"

export SIGNER_ROLE=$(cast keccak "SIGNER_ROLE")
cast call "$CERTIFICATE_ADDRESS" \
  "hasRole(bytes32,address)(bool)" \
  "$SIGNER_ROLE" "$SIGNER_ADDRESS" \
  --rpc-url "$SEPOLIA_RPC_URL"
```

两个角色查询都应返回 `true`。
