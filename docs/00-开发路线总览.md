## 1. 怎么使用这套手册

这不是要求你复制完所有代码再运行的“最终答案”。正确用法是：

1. 从节点 01 开始，不要跳过当前节点的验收。
2. 先阅读“当前节点使用的技术能力”，理解这一层在系统中的作用。
3. 按给出的相对路径创建或修改文件，不要自行改变目录结构。
4. 每完成一小段就运行命令，不要一次粘贴十几个文件后再排错。
5. 看到与手册不同的版本、命令输出或第三方地址时，先查该章节的“常见错误”。
6. 验收清单全部通过后再提交 Git，然后进入下一节点。
7. 任何私钥、数据库 URL、Privy Secret 都只能放在被 Git 忽略的 `.env` 中。

每个节点都固定包含：目标、产物、技术能力、前置条件、操作步骤、关键代码、原理说明、验证方式、预期结果、常见错误、验收清单和 Git 提交建议。

## 2. 最终系统

```text
浏览器（TanStack Router）
  ├─ Privy 登录 / 嵌入式钱包
  ├─ viem 读取与发送链上交易
  └─ tRPC 调用中心化 API
          │
          ▼
Hono + tRPC
  ├─ Privy Access Token 校验
  ├─ 课程、评论、学习进度
  ├─ 购买交易验证
  └─ EIP-712 课程完成证明
          │
          ▼
PostgreSQL + Drizzle

Ethereum Sepolia
  ├─ YDToken（ERC-20）
  ├─ MockUSDC（测试 ERC-20，6 位精度）
  ├─ CourseMarket（课程上架与购买）
  ├─ CourseCertificate（不可转让 ERC-721）
  ├─ Uniswap V3（YD/MockUSDC、YD/WETH）
  └─ Chainlink Functions（可选完成状态验证）
```

## 3. 当前项目基线

Better-T-Stack 已经生成：

```text
apps/web                 React + TanStack Router + Vite
apps/server              Hono Node.js 服务
packages/api             tRPC 路由和业务逻辑
packages/db              Drizzle 与 PostgreSQL
packages/env             环境变量校验
packages/ui              公共 UI 组件
```

本手册将新增：

```text
apps/contracts           Foundry 智能合约工程
packages/contracts       前端/后端共享的 ABI、地址和链配置
docs                     开发手册
```

不要把 Solidity 合约放进 `apps/server`，也不要让浏览器直接访问数据库。

## 7. 推荐 Git 分支与提交习惯

第一次完整开发不要建立大量长期分支。推荐在个人功能分支工作：

```bash
git switch -c feat/web3-university-mvp
```

每个节点一个小提交：

```text
chore(repo): pin node and document env
feat(contracts): add YD token
test(contracts): cover course purchases
feat(api): add course queries
feat(web): add two-step purchase flow
```

提交前至少执行与当前节点相关的检查。不要为了“工作区干净”提交私钥或临时调试文件。

## 9. 全局安全红线

- 不把助记词复制到任何网页或聊天窗口。
- 不用持有真实资产的主钱包做开发。
- 不提交 `.env`、私钥、数据库连接串、Privy Secret。
- 不相信前端传来的 `walletAddress`、`price` 或“交易成功”布尔值。
- 不使用前端课程价格作为合约扣款依据。
- 不把测试合约地址直接写散在多个组件中。
- 不在未理解滑点和 token 顺序前向 Uniswap 池投入真实资金。
- 不在主网上照搬本教程部署。
