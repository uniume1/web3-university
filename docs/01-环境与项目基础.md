# 阶段 A：环境与项目基础

> 节点范围：01～06  
> 阶段目标：脚手架、数据库和本地 EVM 链全部可运行  
> 预计用时：7～9 小时

## 节点 01：认识 Monorepo，跑通脚手架（1 小时）

### 本节点目标

理解现有目录职责，确认生成项目没有基础故障。

### 当前节点使用的技术能力

- **Turborepo**：统一调度多个应用和 package 的脚本，不负责安装依赖。
- **pnpm workspace**：让 `apps/*` 和 `packages/*` 互相使用本地包。
- **TanStack Router**：前端文件路由和类型安全导航。
- **Hono**：提供 Node.js HTTP 服务。
- **tRPC**：共享前后端 API 类型，不生成 REST Swagger。

这些能力共同解决“前端、后端和共享代码如何放在一个仓库中协作”的问题。

### 操作步骤

```bash
pwd
node --version
pnpm --version
pnpm install
pnpm check-types
pnpm dev
```

另开一个终端验证：

```bash
curl http://localhost:3000/
open http://localhost:3001
```

阅读以下文件，不要修改：

```text
package.json
pnpm-workspace.yaml
turbo.json
apps/server/src/index.ts
apps/web/src/main.tsx
packages/api/src/routers/index.ts
packages/db/src/index.ts
```

### 原理说明

根目录 `pnpm dev` 由 Turbo 同时启动 `apps/web` 和 `apps/server`。Web 默认 `3001`，Server 默认 `3000`。页面通过 `VITE_SERVER_URL` 访问 tRPC。

### 验证与预期结果

- `pnpm check-types` 退出码为 0。
- `http://localhost:3001` 能打开。
- 浏览器 Network 中能看到 tRPC 健康检查请求。

### 常见错误

- `DATABASE_URL is required`：说明 Server 启动时没有加载 `apps/server/.env`。
- 端口被占用：用 `lsof -i :3000`、`lsof -i :3001` 查进程，不要盲目杀掉未知服务。
- Node 26 出现依赖兼容问题：节点 02 会切到 LTS。

### 验收清单

- [ ] 我能解释 `apps` 与 `packages` 的区别。
- [ ] Web 和 Server 都能启动。
- [ ] 类型检查通过。

### Git 提交建议

本节点没有文件改动，不需要提交。

## 节点 02：固定 Node/pnpm，建立环境变量模板（1～1.5 小时）

### 本节点目标

把运行时固定到 Node 24 LTS，并给敏感配置建立安全模板。

### 当前节点使用的技术能力

- **nvm**：在一台机器上管理多个 Node.js 版本。
- **`.nvmrc`**：告诉开发者此项目应使用的 Node 主版本。
- **环境变量**：把配置和密钥移出源代码。
- **T3 Env + Zod**：启动时检查环境变量，而不是执行到一半才报错。

### 操作步骤

```bash
nvm install 24
nvm use 24
node --version
```

创建 `.nvmrc`：

```text
24
```

创建 `apps/server/.env.example`：

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE
CORS_ORIGIN=http://localhost:3001
PRIVY_APP_ID=
PRIVY_APP_SECRET=
SEPOLIA_RPC_URL=
SERVER_WALLET_PRIVATE_KEY=
COURSE_PROOF_SIGNER_PRIVATE_KEY=
ETHERSCAN_API_KEY=
```

创建 `apps/web/.env.example`：

```dotenv
VITE_SERVER_URL=http://localhost:3000
VITE_PRIVY_APP_ID=
VITE_SEPOLIA_RPC_URL=
VITE_YD_TOKEN_ADDRESS=
VITE_COURSE_MARKET_ADDRESS=
VITE_CERTIFICATE_ADDRESS=
```

扩展 `packages/env/src/server.ts` 时，先只加入非空校验，开发早期不要一次要求全部第三方密钥：

```ts
PRIVY_APP_ID: z.string().min(1).optional(),
PRIVY_APP_SECRET: z.string().min(1).optional(),
SEPOLIA_RPC_URL: z.url().optional(),
```

### 原理说明

`.env.example` 可以提交，只包含键名和假值；`.env` 不可以提交。敏感配置必须由运行环境注入。

### 验证

```bash
nvm use
git check-ignore apps/server/.env apps/web/.env
git status --short
pnpm check-types
```

两个真实 `.env` 都应该被 Git 忽略。

### 常见错误

- `.env.example` 也被忽略：当前 `.gitignore` 的 `.env` 规则通常不会忽略它；用 `git check-ignore -v` 查来源。
- 把真实连接串复制进 example：立即替换并检查 Git 历史；已提交的密钥必须轮换，删除文件不等于消除泄露。

### 验收清单

- [ ] `node --version` 为 `v24.x`。
- [ ] `.nvmrc` 存在。
- [ ] example 文件不含真实密钥。
- [ ] 真实 `.env` 被忽略。

### Git 提交建议

```bash
git add .nvmrc apps/server/.env.example apps/web/.env.example packages/env
git commit -m "chore(repo): pin node and document environment"
```

## 节点 03：确认 Prisma Postgres，跑通 Drizzle（1～1.5 小时）

### 本节点目标

确认数据库不是即将过期的临时库，创建第一张健康检查表并跑通 Drizzle。

### 当前节点使用的技术能力

- **PostgreSQL**：存储课程、评论、进度等可变业务数据。
- **Drizzle ORM**：用 TypeScript 定义 SQL 表并生成迁移。
- **Prisma Postgres**：这里只是托管 PostgreSQL；项目仍然使用 Drizzle，不使用 Prisma ORM。
- **Migration**：以可追踪文件描述数据库结构变化。

### 操作步骤

如果生成器使用了 `Automatic (create-db)`，数据库默认只保留 24 小时。打开生成时打印的 claim URL 将其认领；如果没有 claim URL，进入 Prisma 控制台确认项目存在。无法确认时，新建长期数据库并替换 `apps/server/.env` 的 `DATABASE_URL`。

临时在 `packages/db/src/schema/index.ts` 创建健康检查表：

```ts
import { pgTable, timestamp, uuid, varchar } from "drizzle-orm/pg-core";

export const systemChecks = pgTable("system_checks", {
  id: uuid("id").defaultRandom().primaryKey(),
  name: varchar("name", { length: 100 }).notNull(),
  createdAt: timestamp("created_at", { withTimezone: true })
    .defaultNow()
    .notNull(),
});
```

检查 `packages/db/drizzle.config.ts` 使用 `DATABASE_URL`，然后执行：

```bash
pnpm db:generate
pnpm db:migrate
pnpm db:studio
```

### 关键代码说明

- `uuid().defaultRandom()` 让 PostgreSQL 生成 ID。
- `withTimezone: true` 避免服务器时区不同导致时间误解。
- schema 是 TypeScript 真相来源，迁移 SQL 是数据库变更记录。

### 验证

在 Drizzle Studio 中确认 `system_checks` 存在，或者使用项目已有 `pg` 连接运行只读查询。

```bash
pnpm check-types
git status --short
```

### 常见错误

- TLS/证书错误：托管 PostgreSQL 通常要求 SSL，使用供应商给出的完整连接串。
- `relation already exists`：不要删除云数据库；先检查迁移表和已执行 SQL。
- 临时数据库消失：重新创建长期数据库并重新执行 migration。

### 验收清单

- [ ] 已确认数据库长期有效。
- [ ] 能生成 migration。
- [ ] 能在 Studio 中看到表。

### Git 提交建议

```bash
git add packages/db
git commit -m "chore(db): verify drizzle migration workflow"
```

## 节点 04：安装 Foundry，认识 forge/cast/anvil（1～1.5 小时）

### 本节点目标

安装 Solidity 开发工具，理解四个主要命令的边界。

### 当前节点使用的技术能力

- **Forge**：编译、测试和部署 Solidity。
- **Cast**：从命令行读取合约、发送交易和查询 RPC。
- **Anvil**：本地 EVM 节点，自动提供测试账户和 ETH。
- **Chisel**：Solidity REPL，本项目不是必需但会随 Foundry 安装。

### 操作步骤

根据 Foundry 官方方式安装：

```bash
curl -L https://foundry.paradigm.xyz | bash
source ~/.zshrc
foundryup
forge --version
cast --version
anvil --version
```

如果已经安装，执行 `foundryup` 升级稳定版即可，不使用 nightly。

### 原理说明

Foundry 是独立于 pnpm 的 Solidity 工具链。不要把 `forge-std` 当 npm 包安装。合约依赖默认位于 `apps/contracts/lib`。

### 验证

```bash
anvil
```

新终端执行：

```bash
cast chain-id --rpc-url http://127.0.0.1:8545
cast block-number --rpc-url http://127.0.0.1:8545
```

预期 Chain ID 为 `31337`。

### 常见错误

- `foundryup: command not found`：重开终端或把 Foundry bin 目录加入 PATH。
- macOS 阻止二进制：确认从官方安装脚本获得，不要下载未知镜像。

### 验收清单

- [ ] Forge、Cast、Anvil 都能输出版本。
- [ ] Anvil Chain ID 为 31337。
- [ ] 能解释 Forge 与 pnpm 的区别。

### Git 提交建议

本节点只安装本机工具，不提交。

## 节点 05：创建 `apps/contracts` 并接入 Turborepo（1.5～2 小时）

### 本节点目标

创建独立 Foundry 工程，并让根目录命令可以调度合约检查。

### 当前节点使用的技术能力

- **Foundry project layout**：`src`、`test`、`script`、`lib` 分离。
- **Solidity remappings**：把 npm 风格 import 映射到 `lib` 目录。
- **Turbo task**：让合约构建成为 Monorepo 质量检查的一部分。

### 操作步骤

```bash
mkdir -p apps/contracts
cd apps/contracts
forge init --force --no-git
forge install OpenZeppelin/openzeppelin-contracts --no-git
```

删除 Foundry 示例 `Counter` 文件可以在确认路径后用普通编辑器删除；不要删除 `lib/forge-std`。

编辑 `apps/contracts/foundry.toml`：

```toml
[profile.default]
src = "src"
test = "test"
script = "script"
out = "out"
libs = ["lib"]
solc = "0.8.30"
optimizer = true
optimizer_runs = 200
fs_permissions = [{ access = "read-write", path = "./deployments" }]

[rpc_endpoints]
anvil = "http://127.0.0.1:8545"
sepolia = "${SEPOLIA_RPC_URL}"

[etherscan]
sepolia = { key = "${ETHERSCAN_API_KEY}" }
```

创建 `apps/contracts/remappings.txt`：

```text
@openzeppelin/contracts/=lib/openzeppelin-contracts/contracts/
forge-std/=lib/forge-std/src/
```

创建 `apps/contracts/package.json`，只用于 Turbo 调度：

```json
{
  "name": "contracts",
  "private": true,
  "scripts": {
    "build": "forge build",
    "test": "forge test",
    "check-types": "forge build"
  }
}
```

创建 `apps/contracts/.gitignore`：

```gitignore
cache/
out/
broadcast/
deployments/*.local.json
.env
```

### 验证

```bash
cd apps/contracts
forge fmt --check
forge build
forge test
cd ../..
pnpm check-types
```

### 常见错误

- OpenZeppelin import 找不到：检查 `remappings.txt` 和 `lib/openzeppelin-contracts/contracts`。
- `forge init` 新建了嵌套 Git：必须使用 `--no-git`，当前仓库只保留根 `.git`。
- Turbo 缓存旧构建：先直接进入 `apps/contracts` 执行 Forge 命令定位。

### 验收清单

- [ ] `apps/contracts` 没有自己的 `.git`。
- [ ] `forge build` 通过。
- [ ] 根目录 `pnpm check-types` 会检查合约。

### Git 提交建议

```bash
git add apps/contracts pnpm-lock.yaml
git commit -m "chore(contracts): add foundry workspace"
```

## 节点 06：启动 Anvil，完成第一次部署与调用（1～1.5 小时）

### 本节点目标

部署一个最小合约，完成“编译 → 部署 → 读取 → 写入”的本地链闭环。

### 当前节点使用的技术能力

- **JSON-RPC**：应用与 EVM 节点通信的协议。
- **部署交易**：没有 `to` 地址、data 中包含合约 bytecode 的交易。
- **eth_call**：只读模拟执行，不消耗 Gas。
- **状态交易**：修改链上状态，需要签名和 Gas。

### 关键代码

创建 `apps/contracts/src/HealthCheck.sol`：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.30;

contract HealthCheck {
    string public message = "Web3 University";

    function setMessage(string calldata nextMessage) external {
        message = nextMessage;
    }
}
```

创建 `apps/contracts/script/DeployHealthCheck.s.sol`：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.30;

import {Script} from "forge-std/Script.sol";
import {HealthCheck} from "../src/HealthCheck.sol";

contract DeployHealthCheck is Script {
    function run() external returns (HealthCheck deployed) {
        vm.startBroadcast();
        deployed = new HealthCheck();
        vm.stopBroadcast();
    }
}
```

### 操作步骤

终端 A：

```bash
anvil
```

复制 Anvil 第一个测试私钥，仅用于本地。终端 B：

```bash
cd apps/contracts
forge script script/DeployHealthCheck.s.sol:DeployHealthCheck \
  --rpc-url http://127.0.0.1:8545 \
  --private-key <ANVIL_TEST_PRIVATE_KEY> \
  --broadcast
```

从输出复制合约地址：

```bash
cast call <CONTRACT_ADDRESS> "message()(string)" \
  --rpc-url http://127.0.0.1:8545

cast send <CONTRACT_ADDRESS> "setMessage(string)" "Hello YD" \
  --rpc-url http://127.0.0.1:8545 \
  --private-key <ANVIL_TEST_PRIVATE_KEY>
```

### 验证与预期结果

再次执行 `cast call` 应返回 `Hello YD`。停止并重启 Anvil 后状态消失，这是本地临时链的正常行为。

### 常见错误

- `insufficient funds`：用错了私钥；Anvil 输出的账户已预充值。
- 地址没有代码：Anvil 已重启，旧部署地址失效。
- 不要把 Anvil 私钥误认为可安全用于公共链；它是公开固定测试私钥。

### 验收清单

- [ ] 我能说明 read call 和 write transaction 的区别。
- [ ] 能部署并读取合约。
- [ ] 能发送状态修改交易。

### Git 提交建议

```bash
git add apps/contracts/src apps/contracts/script
git commit -m "feat(contracts): add local deployment health check"
```
